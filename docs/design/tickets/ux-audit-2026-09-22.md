# Design Ticket: ux-audit-2026-09-22

**What's changing visually/UX-wise:**
- **Mobile nav (Header/MobileNav):** the existing full-screen link list gains
  a trailing account section — "Log In" when signed out, or "My Account" /
  "My Orders" / "Log Out" when signed in — styled identically to the existing
  category links.
- **Product gallery (Product Detail Page):** the static hero image + inert
  thumbnail strip becomes one `ProductGallery` component — a swipeable hero
  (drag follows the finger, releasing past ~15% of the width commits to the
  next/previous image) with a thumbnail strip below that's clickable/tappable
  and shows a gold border on the active image. Keyboard users get left/right
  arrow support on the focused gallery. Visual footprint (aspect-square,
  `border-bone/10`, `bg-surface`, 4-col thumbnail grid) is unchanged.
- **Category tiles (Home Collection section, Shop grids):** add a dark
  linear-gradient scrim behind the tile's text (same technique already used
  on the Hero) plus a text-shadow, so the "No. 01 / Rings" / "Rings" / "Shop
  Rings →" labels stay legible regardless of the photo underneath. No layout
  change — same aspect-3/4 tile, same type scale.
- **Checkout confirmation (Order Confirmation, WhatsApp mode):** heading
  changes from "Thank you. We've received your order." to language that
  reflects the order isn't confirmed until the WhatsApp message is sent, plus
  one added reassurance line above the "Continue on WhatsApp" button.
- **Form field labels (Checkout guest fields, all Auth forms):** a
  non-required field's label gets a muted " (optional)" suffix, rendered the
  same way in both places instead of one hardcoding it into the label string.
- **Product/category grids + account orders:** page-change scrolls the
  results back into view instead of leaving the visitor scrolled at the
  pagination control.
- **Shop, Shop/[category], Product pages:** a small breadcrumb trail
  (Home / Shop / [Category] / [Product]) renders above the existing page
  heading, in the same label-caps micro-type already used for kickers.
- **New global states:** a branded 404 page and a branded error-boundary
  screen, both reusing the existing `ComingSoonPage` layout language (kicker,
  serif headline with an italic accent, centered, one or two CTAs).
- **Privacy / Terms:** replace the "Coming Soon" stub with the existing
  `ContentPage` layout (same one About uses), with a visible "Draft — pending
  legal review" notice at the top of each page.

**Affected screens/states:** Header + MobileNav (every page, mobile
viewport), Product Detail Page (default + loading states — loading state
unchanged), Home (Collection section) + Shop + Shop/[category] (tile grid),
Order Confirmation (WhatsApp success state only — Paystack states unchanged),
Checkout (guest form), Login/Register/Forgot/Reset (shared AuthForm), Shop /
Shop/[category] / Product Detail (breadcrumb + pagination), a new global
not-found state, a new global error state, Privacy, Terms.

**Before/after:**
- Mobile nav: before, no way to reach account. After, account entry point
  matches desktop parity.
- Gallery: before, 3 of 4 product images were unreachable. After, all images
  reachable via swipe, tap, or keyboard.
- Category tiles: before, text contrast depends entirely on the source
  photo. After, guaranteed contrast via scrim, same as Hero.
- Confirmation copy: before, "received" language regardless of whether the
  WhatsApp message was ever sent. After, copy matches what's actually true
  at that point in the flow.

**Component inventory:**
- `ProductGallery` — `[NEW]`, commerce component; replaces the inline
  gallery markup in `ProductDetailView`.
- `Breadcrumbs` — `[NEW]`, shared component; no existing equivalent (only
  invisible JSON-LD existed).
- `app/not-found.tsx`, `app/error.tsx` — `[NEW]` Next.js route conventions;
  visually `[REUSE]` of `ComingSoonPage`'s established pattern (kicker +
  serif headline + CTA), not a new visual language.
- Mobile nav account items, checkout/auth "(optional)" suffix, category tile
  scrim — `[REUSE]`, extending existing `MobileNav`, `Field`/`AuthForm`, and
  `Hero`'s scrim technique respectively. No new primitives.

**Responsive & platform behavior:** the gallery's swipe gesture is the
primary interaction on touch/mobile; the thumbnail strip and arrow keys cover
mouse/keyboard on desktop. Breadcrumbs wrap onto a second line on narrow
viewports rather than truncating (short label set, unlikely to overflow in
practice). Mobile nav change only affects the sub-640px `MobileNav` overlay;
the desktop `AccountMenu` is unchanged.

**Accessibility check:** Yes, this affects contrast, touch targets, and
focus order —
- Category tile scrim: raises text-over-photo contrast to at minimum what
  the Hero already achieves (WCAG 1.4.3 AA, verified visually as a
  follow-up per the audit's `[Verify visually]` flag).
- Gallery thumbnails: real `<button>` elements, `aria-current` on the active
  one, `aria-label` announcing "View image N of M" — each thumbnail is
  already well above the 44×44px minimum touch target (4-col grid inside a
  ≥320px column).
- Gallery hero: `role="group"`, `aria-roledescription="carousel"`,
  `aria-label` stating position (e.g. "2 of 4"), keyboard-operable via
  arrow keys when focused.
- Mobile nav new items: same focus/tab-order treatment as existing links;
  "Log Out" renders as a real `<button>`, not a link styled as one.
- Breadcrumbs: `nav[aria-label="Breadcrumb"]`, current page marked
  `aria-current="page"` and not a link (matches the pattern already used in
  `CategoryChips`/`AccountNav`).

**Design Acceptance Criteria (testable, in addition to the PM ticket's):**
- Swiping the gallery hero more than ~15% of its width commits to the next/
  previous slide; releasing under that threshold snaps back to the current
  image with no residual drift.
- Category tile text meets at least the same contrast margin as the Hero's
  headline against its video background, regardless of which category photo
  is behind it.
- The mobile "Log Out" action closes the menu and returns focus the same way
  an ordinary link tap does, not a jarring full reload.
