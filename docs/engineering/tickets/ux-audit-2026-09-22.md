# Engineering Ticket: ux-audit-2026-09-22

**What changed:**
- `components/layout/MobileNav.tsx`, `components/layout/Header.tsx` — mobile
  nav items can now be a route or an action; Header adds My Account/My
  Orders/Log Out (signed in) or Log In (signed out) to the mobile menu (F1).
- `components/commerce/ProductGallery.tsx` (new), `components/commerce/ProductDetailView.tsx` —
  static hero + inert thumbnails replaced with a pointer-drag swipeable
  carousel + clickable thumbnail strip + arrow-key support (F3).
- `app/globals.css` — added `.t-gallery-slide`, reusing the existing panel
  open/close timing tokens rather than introducing new ones.
- `components/home/CollectionSection.tsx` — replaced the no-op
  `bg-blend-overlay` with an explicit gradient scrim + text-shadow behind
  category tile text, matching Hero.tsx's existing technique (F4).
- `app/order-confirmation/page.tsx` — WhatsApp-mode confirmation copy no
  longer says "received" before the WhatsApp message is sent (F5).
- `components/commerce/CheckoutForm.tsx`, `components/commerce/AuthForm.tsx`,
  `app/account/register/page.tsx` — non-required fields now render
  "(optional)" from one shared code path in each form instead of Register
  hardcoding it into the label string (F6).
- `components/shared/Breadcrumbs.tsx` (new), wired into
  `components/commerce/ShopView.tsx` and `components/commerce/ProductDetailView.tsx`;
  pagination in `ShopView.tsx` and `app/account/orders/page.tsx` now scrolls
  results back into view on page change (F7).
- `app/not-found.tsx`, `app/error.tsx` (new) — branded 404 and error-boundary
  screens, replacing Next.js's default pages (F8).
- `app/privacy/page.tsx`, `app/terms/page.tsx` — real draft content via
  `ContentPage` (which gained an optional `notice` prop for the "pending
  legal review" callout), replacing the `ComingSoonPage` stub (F2, draft
  copy only — not legal-reviewed). `components/shared/ComingSoonPage.tsx`
  removed — no longer referenced anywhere after this change.

**Test added or updated:** No new automated tests. This batch is UI markup,
copy, and CSS-token changes with no new business logic to unit-test; the
gallery's drag-commit threshold (`SWIPE_COMMIT_THRESHOLD`) is a plain
constant, not branching logic worth a dedicated test. Verified instead via:
- `npx tsc --noEmit` — clean
- `npx eslint .` — clean
- `npx vitest run` — 8/9 passing; the 1 failure
  (`formatFulfillmentStatus` expecting `"Payment Confirmed"`, getting
  `"Confirmed"`) is **pre-existing**, confirmed via `git stash` against the
  unmodified tree before this batch — unrelated to this ticket, not touched
  or fixed here.
- Live dev server + real catalog data: server-rendered HTML confirmed via
  curl for the breadcrumb, carousel `aria-roledescription`/thumbnail
  `aria-label`s (all 4 on a 4-image product; none on a 1-image product,
  confirming the `images.length > 1` gate), the category-tile scrim
  gradient, the mobile "Log In" link, the Privacy/Terms draft notice, the
  Register "(optional)" suffix, and a real 404 status + branded copy on an
  unknown route. Automated pixel screenshots were blocked by the pre-existing
  session preloader (see note below); HTML-level verification was used
  instead since Shop/Product/404/Privacy/Terms are server-rendered.
